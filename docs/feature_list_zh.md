# 特性列表

## 未来可能会被支持的特性

- 支持io_uring
- 可视化界面（展示当前cache-cat的运行状态）
- 压缩快照（当字符串长度超过阈值 比如20字节，在快照写入时对单字符串进行压缩）
- 支持Redis的快照文件导入
- MTLS
- 读写分离（自定义redis命令实现）

## 不会被支持的特性
- 淘汰算法（eviction policy）：在任何用到LRU或LFU等算法的场景下，你都应该直接用Redis或者Valkey而不是Cache-cat。原因是显而易见的，Cache-cat使用的是共识算法，相对于Redis确保了数据不会因为单点故障导致数据丢失。如果你的业务语义允许“数据随时可以丢，丢了以后重新从源站加载”，那么你需要的是 Redis/Valkey 这样的 cache；如果你的业务要求“写成功之后，即使发生单节点故障，数据仍然是集群一致状态的一部分”，那么才是 Cache-cat 的使用场景。
